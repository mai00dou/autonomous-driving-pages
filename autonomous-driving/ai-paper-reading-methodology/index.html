问题定义 · Why

人读论文的瓶颈，正是 AI 的切入点

  • 读得慢：一篇前沿论文 + 源码，人工吃透常要一整天；图、表、公式、代码散落各处
  • 留不住：读完笔记零散，几个月后等于没读；跨论文的演进脉络全靠脑子记
  • 难复用：每篇都是孤立的 trick，缺一条统一主线，新论文来了无法快速定位
  • 讲不透：只摘 abstract 和结论，架构细节、维度变化、真实代码很少落到笔记里
AI Agent 的目标
读得透 · 归档准 · 复用强
把「读论文」拆成可重复执行的流水线：每一步都有明确产出、有质量校验、有归档落点。 Agent 不只是总结，而是端到端产出一份能长期复用的技术资产。

03 / 读得透
图文并茂 · Visual

图文并茂不是堆图，是「每张图各归其位」

  • 论文原图：pdffigures2 高 DPI 抽 figure/table，双重校验（整页非白 + 四周留白）才入库
  • 自绘 Graphviz：整体架构 + 子模块 + 真实代码数据流图，竖向 TB、dpi=200 高清
  • 交错写入：写一段文字 → 立刻贴对应图 → 再写下一段，图自然落到该章节
  • 铁律：禁止「图表速查附录」式堆图；每张图都有唯一归属章节，没有无主图
示例：自绘 Graphviz 把 Sparse4D 的 deformable 4D 聚合画成数据流图

06 / 自我进化
沉淀证据 · Lessons Codified

这些坑，踩过一次就再不会踩

🗂️ PDF 完好性

同名论文多版本，损坏版抽出空白图 → 先 md5 + 关键页非白校验，坏了从 arXiv 重拉。

➗ 公式被吞

飞书把 < > 当 HTML 标签吞内容 → 一律换 \lt \gt，公式块不混文字。

🖼️ 图被拉糊

sips -Z 按最长边缩，竖图变细窄条 → 改 --resampleWidth，只缩不放。

📍 图放错位

堆「图表附录」让人工拖 → 交错写入，写一段贴一图，每图归位。

🗄️ 归档丢内容

先建文档再 wiki create 会建空文档 → 先 wiki create 拿 token 再写入。

⚡ 触发限流

并发 delete/insert 触发 429 → 串行操作，从高 index 往低 index 改。

07 / 踩坑沉淀
策略总结 · Strategy

当前论文阅读策略一览

  • 会话隔离：长论文/重度代码解读默认开新 session，不在长会话里反复切题，控成本、防串味
  • 历史压缩：必须续聊时先把上下文压成结论/清单/阶段摘要，不长期携带全量历史
  • 谱系成线：单篇解读完，按技术演进串成主线综述（如 DETR→PETR 14 篇），新论文能秒定位坐标
  • 必归档：技术产出第一时间入飞书知识库对应分类，不停在聊天里；记忆同步进 MEMORY.md
  • 工程导向：每篇都落一条「能怎么搬到 E2E Occupancy 项目」，读论文直接服务于手上的活
谱系成线：14 篇论文串成一张演进树，新论文来了立刻定位
08 / 策略总结
知识资产化 · Knowledge Base

归档不是终点：把 N 篇笔记长成一座论文库

  • 单篇 → 库：每篇解读只是原材料，真正的资产是它们之间被显式写出来的关系；关系不写，库就退化成文件夹
  • 统一元数据：每篇必带 task / backbone / 输入表征 / 监督信号 / 指标 / 一句话创新 / 已知局限，字段固定才可横向对比
  • 三层结构：单篇深读 → 主题综述 → 演进主线；新论文进来只做增量，不动上层骨架
  • 可检索：分类 + 标签 + 索引页，要能回答「谁解决过这个问题」，而不是靠回忆文件名
元数据卡 · 每篇强制七字段
task : 环视 3D 检测 backbone : VoVNet-99 input : 6V 图像 + 3D PE supervision : 稀疏 query 集合 metric : NDS 0.5xx idea : 3D 点投回 2D 采特征 limit : 远距离召回受限
09 / 归档之后
跨论文分析 · Cross-Paper Diff

一堆论文放在一起，差异才是信息

🧮统一维度对比矩阵

同一任务的 N 篇按固定五列对齐：输入表征 / 时序建模 / 监督信号 / 后处理 / 推理成本。表里的空格本身就是结论——整列没人做，那就是空白。

🌿演进树还原 Δ

把后一篇读成「前一篇 + 一个改动」，创新点就从形容词变成可定位的 diff。谁补了谁的第几个缺陷，一眼可查，不必靠记忆。

⚖️共识 / 分歧双栏

大多数论文都做的事是领域默认值；默认值被改写才是大新闻。只有一两篇做的事，是需要验证的分歧点，也最值得复现。

🔍反事实追问

去掉这个模块还成立吗？换掉这个数据集还领先吗？答案往往正是论文的边界条件，比 abstract 里的形容词有用得多。

抽丝剥茧的产出不是「第 N 篇讲了什么」，而是三张表：对比矩阵（谁在哪一列领先）、演进树（谁继承谁）、决策表（我这个场景该选谁）。
10 / 抽丝剥茧
知识保鲜 · Review Loop

结论会过期，回看才是复利

  • 触发式回看：新论文一落地，先回溯同主题旧笔记做增量更新，而不是从零重读一遍
  • 周期回看：月度扫增量（补齐元数据、修失效链接），季度重排主线（谁被超越了、主线是否换向）
  • 回看四问：结论还成立吗 / 被谁超越了 / 工程假设变了吗 / 我上次的判断错在哪
  • 版本化：笔记标「截至 YYYY-MM」+ 置信度，绝不让三年前的结论冒充当下共识
  • 可自动化：把季度回看挂成定时任务，Agent 扫新 arXiv 命中关键词，主动提示哪几篇旧笔记该改

11 / 定期回看
论文库的复利 · Compounding

攒到一定量，读论文开始反向供血

🎯选型决策

新项目要定 backbone，直接查矩阵，不必再读十篇。决策成本从「两周调研」压到「十分钟查表」。

💡选题探测

空白 = 矩阵里整列为空，或共识里没人验证过的假设。别人从零找 idea，你从自己表的空格里找。

✍️写作复用

综述、PPT、答辩材料从主线直接生成，边际成本趋零；同一批素材换切面就能出一版新的。

🧭团队传承

新人从演进树入手，三天建立领域地图；沟通从「你去看那篇论文」变成「看第 3 行第 2 列」。

单篇笔记的价值随篇数线性增长，关系网的价值随连接数超线性增长——这正是「抽丝剥茧 + 定期回看」值得单独做一遍的理由。
