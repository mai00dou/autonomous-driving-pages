一、一句话定位

SparseOcc 是把 DETR 那套「query + 一对一匹配」基因在占据任务上落地得最完整的一篇。它不建任何稠密体素，用 100 个 query 表示场景里的「东西」，前向阶段零稠密计算。

论文 Fully Sparse 3D Panoptic Occupancy Prediction
会议 CVPR 2024 · arXiv 2312.17118
作者 南京大学 + 上海 AI Lab（Haisong Liu 等，与 SparseBEV 同一批人）

二、它要解决什么

稠密体素方法的算力浪费触目惊心：200×200×16 里绝大多数格子是空的（天空、远处、物体内部），但每一格都要参与卷积和注意力。SparseOcc 的立场是——只算有东西的地方。

麻烦在于，占据任务不像检测那样天然有「目标数」这个上界。一个场景里有多少块被占的区域？说不清。而且被遮挡区域根本看不见，稀疏 query 没法从图像里找到它们。所以 SparseOcc 必须造一套稠密信号来辅助训练——这是它比纯稀疏检测复杂的地方。

三、关键技术与源码

3.1 配置里的核心数字

_num_queries_ = 100
_num_frames_  = 8
_num_points_  = 4
_num_groups_  = 4
_num_layers_  = 2
_dim_         = 256
_topk_training_ = [4000, 16000, 64000]
_topk_testing_  = [2000, 8000, 32000]

注意 topk 这组：训练时逐层保留最多 4000 / 16000 / 64000 个体素，测试时降到 2000 / 8000 / 32000。这是稀疏解码器里「用 top-k 控制稠密度」的典型手法——不是完全稀疏，而是「稀疏到可控」。

3.2 一对一匹配搬到了掩码上

self.matcher = HungarianMatcher(cost_class=2.0, cost_mask=5.0, cost_dice=5.0)

这是最能说明「DETR 基因」的一行。检测里的匈牙利匹配比较的是分类分数和框的 L1/GIoU；这里比较的是分类分数、掩码交叉熵、掩码 Dice。匹配对象从「框」换成了「体素掩码」，但「每个真值只配一个预测、不要重复不要遗漏」的约束原封不动。

3.3 解码层：三件套来自 SparseBEV

self.self_attn = MaskFormerSelfAttention(embed_dims, num_heads=8)
self.sampling  = MaskFormerSampling(embed_dims, num_frames, num_groups,
                                   num_points, num_levels,
                                   pc_range=pc_range, occ_size=occ_size)
self.mixing    = AdaptiveMixing(in_dim=embed_dims,

这三件的结构直接来自同组的 SparseBEV 检测头（from .sparsebev_transformer import AdaptiveMixing）。换成占据任务时没有改结构，只是把采样的参考位置从「二维框中心」换成「体素中心」：

in_points = num_points * num_frames = 4 × 8 = 32，正好对应「8 帧、每帧 4 点」的采样规模。

3.4 掩码是怎么算出来的

def inner_pred_segmentation(self, query_feat, mask_feat):
    class_pred = self.classifier(query_feat)
    feat_proj  = self.mask_proj(query_feat)
    mask_pred  = torch.einsum("bqc,bnc->bqn", feat_proj, mask_feat)
    valid_map  = (mask_pred > 0.0)
    return valid_map, mask_pred, class_pred

那一行 einsum("bqc,bnc->bqn") 是整个方法的核心运算：b 是 batch，q 是 100 个 query，n 是体素数，c 是特征维。query 特征投影后与体素特征做点积，得到「每个 query 在每个体素上的归属分数」——这就是 MaskFormer 式的掩码预测。

注意 classifier 输出的是 num_classes - 1，最后那一类留给「空」。

3.5 前向为什么是零稠密

体素特征不来自稠密网格，而来自解码器自己吐出的 occ_loc（体素坐标）+ mask_feat（对应特征）。也就是说，体素集合本身是预测出来的，从 100 个 query 里长出来的，不是预先切好的格子。这是「稀疏」两个字的真实含义。

五、在谱系里的位置

往前：query 思想 ← DETR；采样核 ← SparseBEV；掩码预测 ← Mask2Former。
与 OccFormer 的区别：两者都用 mask 查询，但 OccFormer 在 256×256×32 的稠密栅格上算，SparseOcc 不建栅格。
同一份 occ_size 的陷阱：SparseOcc 的 200×200×16 配 80 米范围，SurroundOcc 的 200×200×16 配 100 米范围。体素边长 0.4 vs 0.5，精度不可直接比。
