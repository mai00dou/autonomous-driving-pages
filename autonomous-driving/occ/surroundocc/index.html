一、一句话定位

SurroundOcc 是稠密体素路线的事实基准。但它的核心贡献不是网络结构，而是把稠密真值造出来——多帧 LiDAR 融合加 Poisson 表面重建。这套流程后来成了整个社区共用的数据基础，没有它，后面所有稠密监督方法都无从训练。

论文 SurroundOcc: Multi-Camera 3D Occupancy Prediction for Autonomous Driving
会议 ICCV 2023 · arXiv 2303.09551
作者 Yi Wei, Linqing Zhao, Wenzhao Zheng, Zheng Zhu, Jiwen Lu, Jie Zhou（清华 + 上海 AI Lab）

二、它要解决什么

2023 年初的车载感知面临一个尴尬：检测框描述不了不规则物体。施工路障、异形车辆、掉落的货物，用轴对齐或带朝向的立方体框都装不下。解决办法是退到体素级——把空间切成小格子，逐格判断「空 / 被占 / 属于哪类」。

但立刻撞上第二个问题：真值从哪来？ 人工标三维占据是不可能的，几十万个格子没人标得动。SurroundOcc 的答案是用多帧 LiDAR 点云累积：单帧雷达稀疏，但在车缓慢行驶时把连续多帧配准叠加，就能把同一片区域扫得足够密；再用 Poisson 重建拟合出表面，把点云变成封闭的体素占据。

三、关键技术与源码

3.1 三层多尺度体素

配置里定义了三组不同的体素分辨率，逐层细化：

_dim_      = [128, 256, 512]
volume_h_  = [100, 50, 25]
volume_w_  = [100, 50, 25]
volume_z_  = [8, 4, 2]
_num_points_ = [2, 4, 8]
_num_layers_ = [1, 3, 6]

注意这里的规模是 100×100×8（最粗）到 25×25×2（最细），不是最终的 200×200×16。最终栅格靠后面的 deblock 上采样得到。粗层负责大范围语义，细层负责边界——这是典型的 FPN 思路搬到三维。

3.2 一个体素 query 怎么取到图像特征

每个体素位置有一个可学习的 embedding，通过 deformable attention 去 6 路环视图像里采特征。核心循环：

for i in range(self.fpn_level):
    volume_queries = self.volume_embedding[i].weight
    volume_embed_i = self.transformer[i](
        [view_features], volume_queries,
        volume_h=volume_h, volume_w=volume_w, volume_z=volume_z,
        img_metas=img_metas)

这里复用的正是 Deformable DETR 那套 deformable attention，只是把参考点从二维换成了三维体素中心，再投影到各相机平面。配置里可以逐个 level 指定采样点数：

deformable_attention.num_points = self.transformer_template.encoder.\
    transformerlayers.attn_cfgs[0].deformable_attention.num_points[i]

这就是「DETR 的采样算子跨任务复用」最直接的证据——同一份 deformable attention 代码，在检测里采二维邻域，在这里采三维体素。

3.3 多尺度监督的衰减权重

三层输出各自算一次损失，但粗层权重被刻意压低，避免低分辨率预测主导梯度：

loss_occ_i = loss_occ_i * ((0.5) ** (len(preds_dicts['occ_preds']) - 1 - i))

最粗一层乘 0.25，中间层乘 0.5，最细一层保持 1.0。

3.4 损失函数：三项组合

语义分支用三项相加：

loss_occ_i = (criterion(pred, gt.long())
              + sem_scal_loss(pred, gt.long())
              + geo_scal_loss(pred, gt.long()))
  • criterion：交叉熵，逐体素分类
  • sem_scal_loss：语义尺度损失，惩罚各类别在整体中的比例偏差
  • geo_scal_loss：几何尺度损失，惩罚「占据 / 空闲」比例偏差

后两项针对的是占据任务特有的类别极度不平衡——绝大多数体素是空的。只算交叉熵会退化成「全预测为空」也有很高准确率。

四、配置里的实际数值

point_cloud_range [-50, -50, -5.0, 50, 50, 3.0] → 100×100×8 米
occ_size [200, 200, 16] → 体素边长 0.5×0.5×0.5 米

use_semantic True，use_grid_mask=True

五、在谱系里的位置

往前：它把 Deformable DETR 的算子搬进三维，是「检测基因跨任务复用」的第一例。
往后：它定义的 0.5 米体素 + 200×200×16 成了后续多篇工作的默认设定；它那套真值生成流程被 Occ3D-nuScenes 等数据集工作继承。
对比 SparseOcc：同样是 200×200×16，但 SparseOcc 的点云范围缩到 ±40 米、体素 0.4 米。两者 mIoU 不能直接比。
